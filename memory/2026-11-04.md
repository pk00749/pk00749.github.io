## 二、学到的新知识 / 教训

1. **模型过载（overloaded）成了今天的主线敌人**。MiniMax 侧返回 `overloaded_error: server is busy`，M2.5 直接 `No available auth profile`（冷却中）。连续错误数已经很能说明问题：
   - daily-viral-article 连挂 **158** 次
   - daily-news 连挂 **108** 次
   - stock-notice-daily 连挂 **60** 次
   - 每日AI课题研究 20 次、workspace-auto-commit 10 次

2. **失败会叠加，不是孤立事件**：模型过载 → 定时任务全灭 → 日志文件缺失 → 记忆断档。今天就是活例子：11-03 和 11-04 的日志文件都缺了，只能靠翻 session jsonl 反推今天干了啥。

3. **cron 的 `consecutiveErrors` 是最该盯的健康指标**，比 `lastStatus` 有用得多。单看 lastStatus 只知道"昨天挂了"，看计数才知道"这活儿已经三个月没干了"。

4. **只跑通的两个任务有共性**：都是**纯执行型**（上传文件、查接口），不依赖复杂推理。所以结论很清楚——AI 层的过载，脚本层照样能干活。**能把任务下沉成确定性脚本的，就别指望大模型心情好**。

5. **GitHub 推送链路今天实际是断的**：`memory/stock/` 最新文件停在 10-29，`git log` 最后一条提交也是 11-02 的 auto commit。10-29 之后的公告一条都没进仓库。

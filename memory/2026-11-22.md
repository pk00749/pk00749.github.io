## 二、学到的新知识 / 教训

1. **过载不是偶发，是常态**。今天 8 个任务里 7 个死于 `overloaded_error` / `No available auth profile`。之前还当它是"服务抽风"，现在看是**默认状态**——把定时任务全押在单一模型上，本质上是把整个自动化命脉系在别人的服务器心情上。
2. **fallback 模型也可能一起死**。M2.7 过载、M2.5 冷却，配成一组等于没配。真正的兜底得是**不同厂商的模型**，同厂双版本不叫降级，叫撞墙。
3. **失败任务会静默留坑**：模型挂掉时，任务连第一步的 `git add` 都没执行，看起来"什么都没发生"，实际上是把整个动作链静默吞掉。**失败必须留痕，不能装作没事。**
4. **coder 仓库反而是今天唯一健康的**——因为它的任务不依赖复杂推理，纯 git 操作能扛住。**任务越简单，越抗造。**
5. **可观测性得靠自己造**：今天全靠翻 `~/.openclaw/cron/runs/*.jsonl` 才拼出全貌。系统状态面板能看单次，看不了全局。

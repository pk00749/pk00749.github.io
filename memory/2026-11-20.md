1. **模型过载会静默杀死定时任务**。daily-log 连续 6 天报 `overloaded_error`（MiniMax M2.7 服务端繁忙 + M2.5 无可用 auth），于是 11-16 至 11-19 四天的日志直接消失。教训：**cron 不能"跑不到就不管"**，至少要有 fallback 模型或失败补偿机制。
2. **cron 任务里写死脚本路径是脆的**。今天两次任务死于 `No such file or directory`——`news-aggregator` 根本没装，`get_stock_notices_detail.py` 也不存在。路径写死 + skill 目录名不一致 = 定时炸弹。
3. **推送环节的"以为成功"最贵**。GitHub API 多次返回 301/404，`git push` 还报 `src refspec master does not match any`（分支名是 `main` 不是 `master`）。真正可靠的是逐条 verify 远端 commit 列表。
4. **凭据明文躺在 .git/config 里**。remote URL 里嵌着 GitHub PAT，等于把钥匙焊在门上。建议改用 credential helper / SSH key，并轮换这枚 token。

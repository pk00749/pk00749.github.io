## 三、学到的新知识 / 教训

1. **域名指 NAT 出口，不指源站**。`203.195.217.95` 是本机 10.1.24.2 的出口，Cloudflare 回源到本机 nginx。**不查这台机器，永远查不出 404 的原因。**
2. **`.openclaw` 目录权限和 nginx 静态托管天然冲突**。正确姿势不是 chmod 777 放宽凭据目录，而是**把静态产物发布到 `/var/www/blog`**，让 nginx 只读它。
3. **YAML front matter 里中文引号是隐形杀手**。11 篇文章同时挂掉，构建日志只报"某文件解析失败"，一篇篇试成本极高。**AI 批量写文章时必须强制校验 front matter。**
4. **动态进程就是运维负债**，今天再次实证：pm2 没起 → 站点离线；Hugo 构建失败 → systemd 疯狂重启 301 万次。**静态发布完就该把 hugo-blog.service 停掉。**
5. **overloaded 不等于"任务没价值"**。AI 课题研究连挂 31 次，失败原因是模型侧过载，不是脚本错。给这类任务挂 `fallbacks` 才靠谱——今天已给 what-is-war 和每日研究加上 `MiniMax-M2.5`。
6. **what-is-war 的数据管线在造假**：`fetch_gdelt.py` 遇 429 无退避、`generate_stats.py` 的 `load_events` 硬编码 `data/ukraine`、`daily-update.sh` 用 `git diff --stat` 退出码判断变更（永远为 0）。结果是**天天往图表里灌 0 事件**，真实事件数据还停在 2026-05-01。**假数据比没数据更危险。**

## 四、有趣的对话 / 发现

- **最有价值的一问来自 YorkLi**："你有多少个博客在线"。随口一问，挖出三个叠加故障、两个 404 站点、一个崩溃循环服务。**最朴素的提问往往指向最深的病灶。**
- **Hugo vs Halo 的结论很清晰**：Halo 是「网站系统」（Java + Spring Boot + 数据库 + 插件供应链 + JVM CVE），Hugo 是「文件生成器」（单二进制、零运行时）。你现在的内容生产已经是 git-native 流水线，**Hugo 赢在你把它变成了一条不出错的流水线；Halo 赢在它是个完整的产品系统——你不需要产品系统。** 真要做付费/会员，选项也应该是 Next.js（你已经有），不是 Halo。
- **Stack 主题两个坑**：RSS.xml 的 Locale bug（历史遗留已修），以及 DeepChat 组件被自建的 Biel 组件替掉。另外 `layouts/_partials` 和 `layouts/partials` 并存——Hugo v0.146+ 已不用下划线版，旧目录是纯遗留，建议删。
- **Hugo 版本落后 11 个 minor**：本机 v0.157，上游 v0.168，Stack 主题对版本敏感。
- **日志断档终于止住**：`memory/` 下 11-14、11-15 连续两天有文件。11-07 至 11-12 那六天的空账还挂着。
- **`hugo-blog.service` 崩溃循环重启 301 万次**——这个数字挺震撼，但也是今天所有故障里最没存在感的那个，因为它平时一声不吭。
